## 1. 文档概述

### 1.1 目的
本文档定义招投标文档智能分析系统的完整功能需求、技术约束和业务规则，为后续系统开发提供明确的规格说明。

### 1.2 范围
本系统是一个Web应用，支持用户创建项目、上传招标和投标文档、进行智能比对分析，并生成详细的评分报告。

### 1.3 术语定义
- **招标文件**: 包含评分标准和要求的采购方文档
- **有效招标文件**: 通过格式验证 + 内容验证（提取到至少1个评分指标）的招标文件
- **投标文件**: 投标方响应招标要求的文档  
- **版本**: 投标文件的不同迭代版本（如v1.0, v1.1等）
- **分析**: 基于招标文件指标对投标文件进行自动评分的过程
- **临时碎片文件**: 断点续传未完成分片（24小时内未完成）、分析临时文件、上传失败缓存文件

## 2. 总体描述

### 2.1 产品愿景
提供一个专业、可靠的招投标文档分析工具，帮助用户快速、客观地评估投标文件质量，提高评标效率和准确性。

### 2.2 用户特征
- 单用户环境使用，系统首次启动需设置本地密码，无密码禁止进入核心功能
- 具备基本的计算机操作能力
- 熟悉招投标业务流程
- 需要处理大量文档分析工作

### 2.3 系统约束
- **部署方式**: Web应用，本地部署
- **文件格式**: Word(.doc/.docx)、PDF(.pdf)、WPS(.wps)
- **并发限制**: 同一时间只能分析一个项目
- **数据持久化**: 所有数据需要持久化存储
- **资源阈值**: JVM堆内存占用＞80%（可配置）触发内存不足告警；单个版本分析时间＞3小时（可配置）触发分析超时

## 3. 功能需求

### 3.1 项目管理

#### 3.1.1 项目创建
- 用户可创建新项目，指定项目名称
- 项目创建后初始状态为"初建"
- 项目名称必须唯一

#### 3.1.2 项目状态管理
项目状态基于版本状态动态计算，不单独存储：

| 状态 | 条件 |
|------|------|
| 初建 | 无有效招标文件 或 无任何投标版本 |
| 就绪 | 有有效招标文件 + 至少一个版本完成文件上传且通过验证、状态为“上传完成” |
| 分析中 | 有版本处于“分析中”状态（且该版本所属项目在全局分析队列中） |
| 部分完成 | 有版本"分析完成" + 有版本未完成 |
| 全部完成 | 所有版本都处于"分析完成"状态 |

### 3.2 文件管理

#### 3.2.1 招标文件管理
- **单次上传**: 每个项目只能上传一次招标文件
- **验证失败补救**: 招标文件验证失败时，允许用户删除该无效文件并重新上传，直至验证通过
- **不可更新**: 验证通过后，永久禁用“重新上传/替换”功能，并在界面标注“招标文件已验证通过，不可修改”
- **更新建议**: 如需更新招标文件，建议创建新项目（如"A项目-更新v1.1"）

#### 3.2.2 投标版本管理
- **自由创建**: 用户可创建任意数量的投标版本
- **自定义版本号**: 版本号完全自定义（如"v1.0"、"初稿"、"2026-03-10修订版"），需满足：
  - 长度≤50字符
  - 禁止包含 `/\:*?"<>|` 等特殊字符，输入时实时校验
- **版本唯一性**: 同一项目内版本号必须唯一，重复时提示：“当前项目内已存在版本号【XXX】，请修改后重试”
- **无数量限制**: 单个项目可创建任意多个版本
- **版本操作规则**: 
  - 未上传文件的版本允许修改版本号/删除
  - 已上传文件的版本仅允许删除文件（保留版本），禁止修改版本号/删除版本

#### 3.2.3 文件上传
- **多文件支持**: 每个版本可上传1个或多个投标文件
- **大小限制**: 
  - 单文件最大300MB
  - 单版本总文件最大1GB
  - 超出则提示“文件大小超出限制，请分割后上传”
- **断点续传**: 
  - 支持大文件分片上传，分片默认10MB（可配置），网络中断可继续
  - 分片有效期24小时，未完成分片自动清理
  - 续传前校验已上传分片哈希值，损坏则重新上传该分片
- **并发上传**: 多项目、多版本可同时上传文件

### 3.3 文件验证

#### 3.3.1 招标文件双重验证
- **格式验证**: 验证文件是否为支持的格式（Word/PDF/WPS）
- **内容验证**: 必须能提取出至少一个有效的评分指标
  - 评分指标定义：包含量化标准、权重、评分方法的内容
  - 验证失败提示："招标文件中未找到有效的评分指标，请检查文件内容"
  - 验证通过后显示预览："检测到X个评分指标，Y个废标条件"

#### 3.3.2 投标文件验证
- **格式验证**: 验证文件是否为支持的格式
- **可解析性**: 验证文件能否成功解析内容，量化标准：
  - 文本型文档：可提取≥80%可读文本
  - 图片型PDF：OCR识别后可提取≥60%文本（OCR失败则判定不可解析）
  - 纯图片无文本：判定为不可解析
- **拒绝无效文件**: 无法解析的文件立即拒绝并提示错误原因
- **无效文件处理**: 版本状态保持“上传中”，界面提示“文件【XXX】解析失败：XXX原因”，允许删除无效文件并重新上传，无效文件不存储（仅记录日志）

### 3.4 分析控制

#### 3.4.1 分析触发
- **手动触发**: 用户必须手动点击"启动分析"按钮才开始处理
- **前置条件**: 只有"上传完成"状态的版本所在项目才能启动分析
- **队列加入**: 点击后立即加入全局分析队列

#### 3.4.2 分析队列管理
- **单项目限制**: 系统同一时间只能分析一个项目
- **FIFO原则**: 按"启动分析"点击顺序排队
- **队列容量限制**: 全局分析队列最大长度100，超出则提示“当前队列已满，请稍后提交”
- **队列持久化**: 系统重启后必须恢复分析队列
- **强制结束**: 
  - 用户可随时强制结束正在分析的任务
  - 结束后版本状态置为“分析失败”，备注“用户强制终止”
  - 任务从队列移除，不自动重试，清理本次分析临时数据
  - 保留已上传文件和检查点数据，支持用户手动“重新分析”

#### 3.4.3 项目内版本队列
- **串行分析**: 单个项目内的多个版本串行分析
- **分析隔离**: 不同版本的分析结果相互独立
- **失败处理**: 分析失败的版本不影响其他版本

### 3.5 分析执行

#### 3.5.1 分析任务检查点
- **状态保存**: 分析过程中的关键节点自动保存状态
  - 文档解析完成
  - 指标提取完成  
  - 内容比对完成
  - 结果生成完成
- **检查点存储**: 与项目/版本数据同目录存储，每个检查点生成唯一MD5哈希值
- **完整性校验**: 系统重启/恢复时校验哈希值，不一致则判定为损坏
- **备份策略**: 关键检查点（文档解析完成、结果生成完成）生成备份副本，主数据损坏时优先用备份恢复
- **中断恢复**: 系统重启后能从最近的检查点继续分析
- **恢复验证**: 恢复时验证检查点数据完整性，损坏则重新开始

#### 3.5.2 评分原则
- **严格依据**: 仅依据招标文件中的明确指标进行打分
- **不得发散**: 不得进行主观判断或超出招标文件范围的评估
- **废标检测**: 识别不符合强制性要求的内容

#### 3.5.3 分析输出
- **废标项**: 列出所有不符合强制性要求的项目
- **得分情况**: 详细展示各项评分指标的得分
- **综合得分**: 计算并显示总分

### 3.6 错误处理

#### 3.6.1 错误分类处理
- **文件错误**:
  - 格式不支持 → 弹窗+页面红色文字提示："文件格式不支持，请上传Word/PDF/WPS格式文件"，记录操作日志
  - 文件损坏 → 弹窗+页面红色文字提示："文件已损坏，请重新上传"，记录操作日志
  - 文件过大 → 弹窗+页面红色文字提示："文件超过大小限制（单文件≤300MB/单版本总文件≤1GB），请分割后上传"，记录操作日志
  
- **内容错误**:
  - 无评分指标 → 弹窗+页面红色文字提示："招标文件中未找到评分指标，请检查文件内容"，记录操作日志
  - 投标文件空白 → 弹窗+页面红色文字提示："投标文件内容为空，请检查文件"，记录操作日志

- **分析错误**:
  - 内存不足 → 页面顶部常驻提示+弹窗："分析过程中内存不足（JVM堆内存占用＞80%），请关闭其他程序后重试"，记录分析日志，可选邮件告警
  - 超时中断 → 页面顶部常驻提示+弹窗："分析超时（单个版本分析时间＞3小时），请尝试重新分析或联系管理员"，记录分析日志，可选邮件告警

- **系统错误**:
  - 磁盘空间不足 → 页面顶部常驻提示+弹窗："磁盘空间不足（剩余＜10GB或总容量10%），请清理空间后重试"，记录系统日志并触发管理员告警
  - 权限问题 → 页面顶部常驻提示+弹窗："文件访问权限错误，请检查系统权限设置"，记录系统日志并触发管理员告警

#### 3.6.2 失败处理机制
- **不自动重试**: 系统不会自动重新分析失败的版本
- **手动重试**: 用户可在版本详情页手动点击"重新分析"
- **隔离处理**: 失败版本不影响同项目的其他版本分析
- **错误详情**: 提供详细的失败原因和建议解决方案

### 3.7 用户反馈

#### 3.7.1 队列反馈
- **队列位置**: 实时显示当前项目在队列中的位置
- **预计等待时间**: 
  - 计算逻辑：预计等待时间 = 已排队项目的历史平均耗时（按文件页数加权） + 当前任务剩余预估耗时；历史平均耗时每小时更新（基于近7天数据）
  - 偏差说明：界面标注“预计等待时间±20%，实际可能因文件复杂度/系统资源调整”
- **动态调整**: 预估时间根据实际分析进度动态调整
- **保守估算**: 偏向保守估计，避免用户失望

#### 3.7.2 状态可视化
- **项目列表**: 显示项目状态、队列位置、预计等待时间
- **项目详情**: 显示各版本状态、分析结果、操作按钮
- **全局状态栏**: 显示当前分析进度和系统状态
- **进度通知**: 分析开始/完成时主动通知用户

## 4. 非功能需求

### 4.1 性能需求

#### 4.1.1 响应时间
- 页面加载: < 2秒
- 文件上传: 支持大文件，进度实时显示
- 分析启动: 立即加入队列，< 1秒响应

#### 4.1.2 并发能力
- **上传并发**: 支持多项目、多版本同时上传文件
- **分析串行**: 分析任务严格串行执行，避免资源竞争
- **队列容量**: 全局分析队列最大长度100

### 4.2 安全需求

#### 4.2.1 输入验证
- **路径安全**: 所有用户输入严格验证，防止路径遍历攻击
- **文件名安全**: 文件名特殊字符过滤和转义
- **版本名安全**: 版本名输入验证（长度≤50字符、禁止特殊字符）和长度限制

#### 4.2.2 文件安全
- **格式白名单**: 仅允许指定的文档格式
- **大小限制**: 单文件≤300MB、单版本总文件≤1GB
- **内容扫描**: 可选的恶意内容检测

### 4.3 可靠性需求

#### 4.3.1 数据持久化
- **项目数据**: 所有项目信息持久化存储
- **文件存储**: 上传的文件持久化保存
- **队列状态**: 分析队列状态持久化
- **分析结果**: 分析结果持久化存储

#### 4.3.2 系统恢复
- **重启恢复**: 系统重启后恢复所有状态和队列，恢复优先级：先恢复项目/版本状态 → 恢复分析队列（按持久化顺序） → 恢复未完成分析任务（从最近检查点）；恢复过程记录日志，失败则标记异常
- **中断恢复**: 分析任务支持从中断处继续
- **数据一致性**: 
  - 文件上传/状态变更采用事务机制，数据库记录与文件存储状态一致
  - 每日校验数据库记录与实际文件的一致性，不一致则标记异常并通知管理员

### 4.4 可维护性需求

#### 4.4.1 日志记录
- **操作日志**: 记录用户关键操作
- **系统日志**: 记录系统运行状态和错误
- **分析日志**: 记录分析过程和结果

#### 4.4.2 监控告警
- **资源监控**: CPU、内存（JVM堆内存占用＞80%告警）、磁盘使用情况监控
- **队列监控**: 分析队列长度和等待时间监控
- **错误告警**: 关键错误（磁盘空间不足、权限问题）自动告警

## 5. 存储管理

### 5.1 文件存储策略

#### 5.1.1 文件分类
- **永久文件**: 招标文件、投标文件、分析结果文件
- **临时文件**: 断点续传分片、分析过程临时文件

#### 5.1.2 自动清理策略
- **清理对象**: 自动清理超过100天的临时碎片文件（断点续传未完成分片、分析临时文件、上传失败缓存文件）；清理时校验文件类型+创建时间，仅清理符合条件的碎片
- **保留对象**: 完整的招标文件、投标文件、分析结果文件不清理
- **清理时机**: 系统启动时和每日定时清理
- **手动清理**: 提供手动清理临时文件的功能

### 5.2 磁盘空间管理
- **空间监控**: 实时监控磁盘使用情况
- **上传前检查**: 上传前检查可用磁盘空间，低于10GB或总容量10%（取较大值），拒绝上传并提示“磁盘空间不足，请清理后重试”
- **空间不足提示**: 磁盘空间不足时及时提示用户

## 6. 用户界面需求

### 6.1 页面结构

#### 6.1.1 项目列表页
- 项目名称、状态、创建时间
- 队列位置和预计等待时间（如果在队列中）
- 创建新项目按钮

#### 6.1.2 项目详情页
- 招标文件上传区域（单次上传，验证通过后禁用）
- 投标版本列表（按状态分组显示）
- 版本创建和管理功能（含版本号校验）
- 全局分析控制按钮

#### 6.1.3 版本详情页
- 该版本的文件上传区域（含大小限制提示）
- 文件列表和状态显示（含解析失败提示）
- 分析控制按钮（根据状态显示不同按钮）
- 分析结果展示（如果已完成）

#### 6.1.4 分析结果页
- 废标项列表（如果有）
- 详细得分情况表格
- 综合得分显示
- 导出报告功能：支持导出单版本分析报告（PDF/Word）、项目内多版本得分对比表（Excel）

### 6.2 状态可视化

#### 6.2.1 颜色编码
- **等待上传**: 灰色卡片
- **上传中**: 蓝色卡片 + 进度条
- **上传完成**: 绿色卡片 + "启动分析"按钮
- **分析中**: 黄色卡片 + 旋转动画
- **分析完成**: 紫色卡片 + "查看结果"按钮
- **分析失败**: 红色卡片 + "重新分析"按钮

#### 6.2.2 按钮状态控制
- **招标文件上传**: 只能点击一次，上传完成且验证通过后禁用
- **版本创建**: 可随时创建新版本，版本名必须唯一（实时校验）
- **启动分析**: 只有"上传完成"状态的版本所在项目才能启动分析
- **重新分析**: 只有"分析失败"状态的版本才能重新分析
- **强制结束**: 分析中状态显示"强制结束"按钮（点击后按规则处理状态）

## 7. 系统边界

### 7.1 包含功能
- 项目创建和管理
- 招标文件上传和验证（含失败补救）
- 投标版本管理和文件上传（含版本号约束）
- 智能分析和评分
- 结果展示和导出（支持PDF/Word/Excel基础报表）
- 队列管理和状态监控
- 单用户访问控制（本地密码验证）

### 7.2 不包含功能
- 用户认证和权限管理（仅支持单用户本地密码验证，无多用户权限）
- 多租户支持
- 移动端专用界面
- 第三方集成（如邮件通知、API接口）
- 高级报表和统计分析（无跨项目统计/趋势分析）
